## What Problem Does It Solve?

[[S3 Requester Pays]] shifts certain S3 access costs from the bucket owner to the person or account downloading the data.

It solves the problem of:

> **"How can I share a large S3 dataset without paying the data-access and download costs generated by everyone who uses it?"**

Normally:

Bucket Owner  
↓  
Pays Storage  
+  
Pays Request Costs  
+  
Pays Data Transfer Costs

With Requester Pays:

Bucket Owner  
↓  
Pays Storage

Requester  
↓  
Pays Request Costs  
+  
Pays Data Download Costs

> [!tip] Memory Trick
> **Requester Pays = You want the data? You pay to retrieve it.**

---

## Normal S3 Cost Model

Normally, the:

**Bucket owner**

pays the costs associated with the bucket.

This includes costs such as:

- S3 storage
- S3 requests
- Data transfer

Architecture:

Bucket Owner  
↓  
Stores Dataset  
↓  
External User Downloads  
↓  
Bucket Owner Receives the Bill

This can become expensive if:

- Dataset is very large
- Many external users download it
- Data-transfer volume is high

---

# Requester Pays Cost Model

With:

[[S3 Requester Pays]]

the requester pays for:

- S3 request costs
- Data download / transfer costs

while the bucket owner continues paying for:

**Storage**

Architecture:

Bucket Owner  
↓  
Stores Dataset  
↓  
Requester Downloads  
↓  
Requester Pays Request + Download Costs

### Memory Trick

**Owner stores it**

**Requester moves it**

---

# Who Pays What?

| Cost | Bucket Owner | Requester |
|---|---:|---:|
| S3 Storage | ✅ | ❌ |
| Request Cost | ❌ | ✅ |
| Data Download / Transfer | ❌ | ✅ |

This is the core exam distinction.

> [!warning] Exam Rule
> **Requester Pays does NOT make storage free for the bucket owner.**
>
> The owner still pays:
>
> **Storage costs**

---

# Why Use Requester Pays?

The strongest use case is:

**Sharing large datasets with other AWS accounts**

Suppose a research organization stores:

50 TB of public research data.

Many companies want to download the dataset.

Without Requester Pays:

Research Organization  
↓  
Pays Every User's Download Costs

With Requester Pays:

Research Organization  
↓  
Pays Storage

Each Consumer  
↓  
Pays Own Request + Download Costs

This makes large-scale data sharing much more sustainable.

---

# Large Dataset Architecture

Example:

Data Provider  
↓  
S3 Bucket  
↓  
Requester Pays Enabled

Then:

Account A  
↓ Download  
Pays Own Costs

Account B  
↓ Download  
Pays Own Costs

Account C  
↓ Download  
Pays Own Costs

The data provider does not absorb all of the download costs.

> [!tip] Architecture Pattern
> **Large shared dataset + external consumers + cost shifting**
>
> → **Requester Pays**

---

# Requester Must Be Authenticated

Requester Pays is designed around:

**Authenticated requesters**

The requester must identify themselves so AWS knows:

> **Which account should be billed?**

Conceptually:

Requester  
↓  
AWS Credentials  
↓  
Requester Pays Request  
↓  
S3  
↓  
Charge Requester's AWS Account

This is different from anonymous public access.

---

# Requester Acknowledges the Charges

When accessing a Requester Pays bucket, the requester must indicate that they:

**Agree to pay the request charges**

Think:

Request  
↓  
"I am the requester and agree to pay"  
↓  
S3 processes request  
↓  
Requester billed

### Architecture Thinking

AWS needs an explicit way to know:

> **The requester accepts the charge.**

---

# Requester Pays Does Not Grant Access

This is extremely important.

Enabling Requester Pays does NOT automatically allow someone to access the bucket.

Normal S3 authorization still applies.

Examples:

- [[IAM Policies]]
- [[S3 Bucket Policies]]
- Cross-account permissions

Architecture:

Requester  
↓  
Authorization Check  
↓  
Allowed?  
├── No → Access Denied
└── Yes → Continue
       ↓
Requester Pays
       ↓
Requester billed

> [!warning] Exam Trap
> **Requester Pays = Billing**
>
> **NOT Permissions**

---

# Requester Pays + Bucket Policy

Suppose:

Account B

needs access to:

Bucket in Account A

The architecture may require:

[[S3 Bucket Policies]]

to grant Account B permission.

Then:

Requester Pays

determines:

**Who pays the request/download costs**

### Memory Trick

**Bucket Policy = Can you access it?**

**Requester Pays = Who gets the bill?**

---

# Requester Pays vs Pre-Signed URLs

These solve very different problems.

## [[S3 Pre-Signed URLs]]

Purpose:

**Temporary access**

Question:

> How can a user temporarily access a private object?

---

## Requester Pays

Purpose:

**Shift request/download cost**

Question:

> Who should pay for retrieving the data?

### Exam Decision

**Temporary private access**
→ Pre-Signed URL

**Consumer should pay download costs**
→ Requester Pays

---

# Requester Pays vs Public Bucket

A public bucket answers:

> **Who can access the data?**

Requester Pays answers:

> **Who pays for requests and downloads?**

These are separate concerns.

### Architecture Thinking

Access Control  
≠  
Billing Control

Do not choose Requester Pays simply because the dataset is shared externally.

Look for the cost requirement.

---

# Requester Pays vs S3 Storage Classes

[[S3 Storage Classes]] reduce the cost of:

**Storing data**

Requester Pays changes who pays:

**Request and download costs**

### Memory Trick

**Storage Class = How much storage costs**

**Requester Pays = Who pays access costs**

# Architecture Thinking

## Scenario 1 — Scientific Dataset

A university stores a huge scientific dataset in S3.

Researchers in other AWS accounts download the data frequently.

The university wants to continue paying for storage but does not want to pay every researcher's download costs.

**Choose → S3 Requester Pays**

---

## Scenario 2 — Cross-Account Dataset Sharing

A company provides large datasets to customers in other AWS accounts.

Each customer should pay for:

- Their S3 requests
- Their data downloads

**Choose → Requester Pays**

---

## Scenario 3 — Reduce Storage Cost

A company wants to reduce the monthly storage cost of rarely accessed objects.

**Do NOT choose → Requester Pays**

Choose an appropriate:

[[S3 Storage Classes|S3 Storage Class]]

or:

[[S3 Lifecycle Rules]]

---

## Scenario 4 — Temporary Private Download

A customer needs temporary access to one private PDF.

The company does not care about shifting the download cost.

**Do NOT choose → Requester Pays**

Choose:

[[S3 Pre-Signed URLs|Pre-Signed URL]]

---

## Scenario 5 — Requester Has No Permissions

Account B tries to access a Requester Pays bucket but has no S3 permission.

Will paying for the request grant access?

**No.**

The requester must still be:

**Authorized**

---

# Scenario Recognition

## Immediately Think Requester Pays When You See

- Large shared dataset
- External AWS accounts
- Consumer pays download
- Shift data-transfer costs
- Shift request costs
- Dataset provider wants to avoid download charges
- Requester billed instead of owner

### Strongest Exam Pattern

> **"Bucket owner should pay storage, but users downloading the dataset should pay access costs."**
>
> → **S3 Requester Pays**

# Exam Traps

## Trap 1 — Requester Pays Means Requester Pays Storage

False.

The:

**Bucket owner still pays storage**

The requester pays:

- Requests
- Downloads / data transfer

---

## Trap 2 — Requester Pays Grants Cross-Account Permission

False.

Use:

[[S3 Bucket Policies]]

or other IAM permissions for access.

Requester Pays only changes:

**Billing responsibility**

---

## Trap 3 — Requester Pays Is Mainly for Temporary Access

False.

That is:

[[S3 Pre-Signed URLs]]

Requester Pays is mainly about:

**Cost allocation**

---

## Trap 4 — Bucket Owner Pays Nothing

False.

The bucket owner still pays:

**Storage**

---

## Trap 5 — Requester Pays Is a Storage Class

False.

It does not change:

- Durability
- Availability
- Retrieval speed
- Storage tier

It changes:

**Who pays for requests/downloads**

## Master Memory Trick

> [!tip] Master Memory Trick
> **Requester Pays = Bring Your Own Bill**
>
> The bucket owner says:
>
> **"I'll pay to STORE the dataset."**
>
> But:
>
> **"If YOU want to download it, YOU pay for the request and transfer."**

Remember:

**OWNER**
→ Storage

**REQUESTER**
→ Requests + Downloads

And never mix up:

> **Permissions decide WHO can access**
>
> **Requester Pays decides WHO pays**
